# 学校数据迁移

NPClassworks 提供学校管理员可操作的加密整校迁移包，用于把一个学校从旧服务器迁入尚未初始化的新服务器。它与部署人员使用的 PostgreSQL 整库备份用途不同：迁移包只包含所选学校的业务数据，不包含实例环境密钥、数据库密码或 Classworks 1 遗留数据。

## 权限与安全

- 只有所选学校的 `OWNER` 或 `ADMIN` 可以生成迁移包；
- 本地管理员必须再次输入个人 PIN；OAuth 管理员需要输入完整学校代码确认；
- 迁移包使用 `scrypt + AES-256-GCM` 加密并校验完整性；
- 迁移密码至少 12 个字符，不写入数据库，也不记录到审计日志；
- 新服务器导入前必须使用 `BOOTSTRAP_SETUP_KEY` 建立安装会话；
- 导入后必须用迁移过来的 OWNER 账号完成上线前登录测试。

## 数据范围

迁移学校、学期、年级、学科、行政班与走班教学班、账号与职责、学生名册与考勤、作业通知及历史版本、大屏账号、通知回执、审计记录和学校级作业设置。

以下数据会被排除或重置：

- JWT、Refresh Token 和所有网页登录会话；
- OAuth Access Token/Refresh Token；
- 大屏设备指纹、设备 Token、心跳状态和待执行命令；
- 实例 `.env` 中的数据库、JWT、指标与初始化密钥；
- Classworks 1 的 Device、KV、AppInstall 和 AutoAuth 数据；
- 浏览器 localStorage 中的学生选班和本地完成标记。

本地账号 PIN 哈希、学校通用教师密码哈希和大屏 PIN 哈希会保留，因此原凭据仍然有效。大屏账号保留，但设备必须重新登录绑定。

## 操作流程

1. 在旧服务器的“学校管理 → 服务器迁移”中选择学校。
2. 检查统计数量，生成并另外保存迁移密码。
3. 输入当前管理员 PIN，下载 `.npcw-transfer` 文件。
4. 在新服务器部署相同或更新版本的前后端，但不要创建学校。
5. 打开新服务器 `/setup`，输入新服务器自己的 `BOOTSTRAP_SETUP_KEY`。
6. 在“管理员、学校与学期”中展开“从旧服务器迁入整校数据”。
7. 上传文件、输入迁移密码并执行预检。
8. 核对学校代码和数据数量后确认导入。
9. 使用原 OWNER 短账号和 PIN 完成上线前登录测试，再锁定 OOBE。
10. 暂停旧服务器的正式写入，切换业务域名 DNS，并逐台重新登录大屏。

## 当前限制

- 目标必须是没有学校、账号、学期、教学空间和发布数据的空白实例；
- 不支持把迁移包合并到已经运行的实例；
- 不自动修改 DNS、反向代理或服务器 `.env`；
- 当前导出是数据库一致性快照，但尚未自动将旧学校切换为只读；最终导出后应由管理员停止旧服务器上的写入；
- 单个上传包上限为 64 MB；超过时应使用部署人员的数据库级迁移工具；
- 目标后端不能比迁移包格式所要求的版本更旧。

## 回退

切换后至少保留旧服务器和迁移前数据库备份 72 小时。新服务器尚未产生正式写入时，可以把 DNS 指回旧服务器。若新服务器已经产生新作业或通知，不应直接回退，否则这些新数据不会自动合并回旧服务器。

迁移功能不是持续同步，也不采用双写。一次迁移只能有一个正式写入端。
