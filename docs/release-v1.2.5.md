# NPClassworksKV v1.2.5 · Hitori（后藤一里）

## 版本概述

v1.2.5 是基于 v1.2.0 的预授权配对、定时监测保护与安全更新，沿用代号 **Hitori（后藤一里）**，按正式版发布。配套 **NPClassworks v1.2.5** 与 **NPEduTools v1.0.0 · EVA-01（初号机）**。

服务端仍负责身份、授权、规则、请求和统计；网页负责学校管理与展示，桌面负责实际设备操作与采样。v1.2.0 已有的通知、远程考试／日常切换、考试方案和原生噪音报告继续保留。

## 新增功能

### 大屏预授权与一次性配对

- 提供单屏及当前学期年级／全校的批量预授权接口。限定学校、启用的班级与现有启用大屏；未来新建大屏不会自动继承此次开放。
- 被授权的网页大屏可用自己的凭据生成 **8 位、10 分钟有效的一次性配对码**。桌面兑换后取得固定归属，管理员无需实时批准；旧桌面申请与管理员审批流程继续可用。
- 兑换和确认在事务中核验学校、绑定、登录凭据版本、预授权版本和部署代际。已占用大屏不能被新设备替换，生成新码使旧的未兑换码失效。
- 批量预览覆盖实际名单与版本；提交时重建并核对摘要。范围变化返回冲突，整批回滚；关闭预授权不撤销已经连接的设备。

### 定时监测管理与展示协议

- **0.8 保护管理**：核验学校管理 PIN 后停止定时监测，按当前学期的班级／年级范围管理返回展示时长；支持修订冲突检查。
- **限时返回作业板**：默认 **10 分钟**，可配置 **1–60 分钟**。返回登记与实际采集分开；重复请求不延长期限，时段和会话变化后旧返回不能沿用。
- **0.9 展示状态**：接收网页可见、返回、受阻与隐藏心跳，供桌面观察；超时表现为未知，不能推断麦克风已经停止。
- 统一网页与桌面的返回租约；离线返回恢复连接时可补登记已开始的期限，不因重连重新计时。采样结束报告仍按既有会话去重。
- 保留 0.6／0.7 采样与学校排程结构。新显示能力必须按协议判断，不能仅凭设备在线就认定支持。

## Bug 修复与安全改进

- 加强学校与账号的租户边界、管理权限、会话撤销及凭据轮换；相关请求重新核验有效身份和作用范围。
- OAuth 交接绑定浏览器验证信息，改进一次性状态处理；私有 Socket 订阅不再只依赖客户端传入的房间范围。
- 修正发布历史及相关接口的授权边界，避免越过学校、工作区或账号权限读取和管理。
- 限定指标接口的 Bearer 授权方式；保留合法的登录、撤销与现有业务流程。
- 对保护停止、返回登记和展示心跳核对实际绑定及会话，拒绝旧序号、变更内容的重复请求和跨会话证据。
- 先前尝试的部署代理协议改动已经撤回，不属于本版；不要求改动 NPEssentials。

## 版本与运维

- 服务页、诊断及 `/check` 等版本入口继续读取统一包元数据，本版为 **1.2.5 / Hitori（后藤一里）**。
- 预授权、展示租约与心跳分别存储，避免把授权开放、设备已连接、画面可见和实际采集混为同一状态。
- NPEP 仍要求环境开关、持久化部署身份和数据库登记一致；保留既有身份与恢复代际规则。
- 本版仅接收噪音统计和必要状态，不接收原音频或摄像头信息；dBFS 不是校准声压级，不提供班级噪音排名。

## 测试与发布保障

- 本次范围依据 v1.2.0 至已合并 main 的实际 Diff，核对 #2、#3、#4 的 PR、旧库升级及跨端记录。
- 已合并预授权通过旧库升级、真实 HTTP／SQL／.NET 和固定三端联合验收；定时保护与展示经过十七阶段隔离验收。此前数据只作为对应功能的历史证据。

## 升级与兼容性

### 相对于 v1.2.0 新增的三项迁移

| 迁移 | 作用 |
| --- | --- |
| `20261002000000_npep_screen_pairing` | 大屏预授权、授权修订与一次性网页配对码 |
| `20261004010000_noise_display_return` | 学校返回时长设置、返回租约与幂等管理记录 |
| `20261004020000_noise_display_presence` | 定时监测网页展示状态与有序心跳 |

使用完整 Prisma 迁移链，不手工挑选 SQL，也不编辑生成客户端来代替迁移。

### 升级顺序

1. 备份 PostgreSQL、服务配置、当前运行版本与 NPEP 外部身份目录；单独数据库转储不包含 `deployment.json` 和身份卷。
2. 先更新 KV 并执行 `prisma migrate deploy`，核对服务就绪；再更新 NPClassworks v1.2.5，最后升级需要新展示保护能力的大屏至 NPEduTools v1.0.0。
3. 已激活服务保留原身份、凭据及设备登记，**不要重复首次初始化或重新激活**。尚未启用 NPEP 的部署可继续保持关闭，原有业务不会因此要求学校配对。
4. 既有预授权默认不开启。检查当前学期、启用的班级和大屏；批量预览变化时重新确认，不无限自动重发提交。
5. 检查学校定时时段、管理 PIN、返回时长及 ClassIsland 时间。服务端修改或撤销无法立即通知离线设备，需要立即停止时在设备端处理。
6. 本地开发继续使用锁定依赖和原生 PostgreSQL，可运行 `pnpm debug:prepare` 后由前端 `pnpm dev` 统一启动。生产配置、凭据及数据不得作为 Release 附件。

### 回退

代码回退与数据库恢复是两项不同操作。保留新增表、身份及备份后写入的数据，不把数据库恢复当作普通应用回退；确需恢复时按 NPEP 的部署代际和旧授权处理流程执行。不要清空持久化卷或用旧身份直接覆盖当前身份。
