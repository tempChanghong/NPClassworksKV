# Classworks 2.0 第五阶段 D：无邮箱快捷登录

本阶段把教师登录从“必须有邮箱和 OAuth”改为学校级可配置策略，同时保留原 OAuth 与邮箱预分配代码。

## 推荐策略

默认使用 `LOCAL_PIN`：教师登录只需学校、短账号和个人 4～8 位数字 PIN。每次登录都会创建独立的 `AccountSession`，访问令牌短期有效，刷新会话默认保留 180 天，因此常用设备通常只需登录一次。

学校初始化时可选择：

- `LOCAL_PIN`：每位教师一个短账号和个人 PIN，推荐。
- `SHARED_PASSWORD`：每位教师有独立短账号，但共用一个学校教师口令。使用最简单，但知道口令的人可以冒用其他教师。
- `OAUTH_EMAIL`：沿用 OAuth 邮箱登录和待认领邀请。

`allowOAuthFallback` 可以在前两种模式下额外展示 OAuth 备用入口。后端授权也会执行学校策略：关闭 OAuth 后，旧 OAuth 教师账号即使仍有历史成员记录，也不能读取或发布该校教学空间；学校 OWNER/ADMIN 不受影响，以免管理员被锁在系统外。

## 首次部署

1. 运行 `pnpm run deploy:init`，生成包含随机 `BOOTSTRAP_SETUP_KEY` 的生产环境文件。
2. 打开 `/classworks-admin`，输入初始化密钥、学校代码、管理员短账号、姓名和个人 PIN。
3. 创建成功后载入七班制模板，确保模板中的学校代码与上一步一致，并按最终名单核对五至七班各自定科。
4. 选择教师认证模式，预检并正式导入组织配置。
5. 在“教师分配”页填写教师短账号、姓名、个人 PIN（通用口令模式不需要个人 PIN）和负责的教学空间。

初始化密钥只在数据库中还没有学校、也没有本地初始化账号时有效。它不会成为日常登录口令，部署后应继续作为服务器秘密保存。

默认禁止普通 OAuth 用户抢先初始化空实例。只有显式设置 `ALLOW_OAUTH_BOOTSTRAP=true` 才恢复旧行为；新部署不建议开启。

## 教师与学生使用

- 教师进入 `/classworks-2`，选择学校后输入短账号和 PIN/通用口令。
- 登录失败限制按“设备 + 学校 + 短账号”隔离；反复输错只限制当前设备，不会全局锁定教师账号。
- 学生无需教师账号，仍按原设计自行选择行政班和走班教学班；选班结果保存在当前浏览器。

## 密码处理

- 个人 PIN 和学校通用教师口令均只保存 bcrypt 哈希，不保存明文。
- 学校通用口令至少 8 个字符；个人 PIN 为 4～8 位数字，实际建议使用 6 位。
- 校园出口通常共用公网 IP，因此本地登录采用“设备与账号组合限流 + 宽松 IP 总量保护”，兼顾防爆破与共享出口可用性。
- 学校代码、教师短账号不是秘密；真正的认证因子是个人 PIN 或通用口令。

## API

- `GET /accounts/local/status`：查询是否需要首次初始化。
- `POST /accounts/local/bootstrap`：用一次性初始化密钥创建首位管理员。
- `POST /accounts/local/login`：学校短账号登录。
- `POST /api/v2/admin/local-teachers/import?dryRun=true`：预检/创建本地教师并分配教学空间。
- 原 `/accounts/oauth/*` 与 `/api/v2/admin/workspace-memberships/import` 保持兼容。
