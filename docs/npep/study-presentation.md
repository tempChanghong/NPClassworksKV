# 原生自习展示回执（本地增量，2026-10-10）

配置应用、窗口回报和新鲜采样是三个事实。本轮沿用纯 WPF，没有新增浏览器进程、截图或传感器采集。

- 正式 MainWindow 复用既有约 500ms 展示轮询，在界面线程读取 StudyWindow 可见/加载/最小化状态及 StudySurface 更新年龄，经 `study.presentation` Named Pipe 上报。可见须学校状态仍新鲜、界面更新小于 1 秒；窗口还在但学校状态已过期时上报 Stale。
- Host 只接受当前展示实例、配置、窗口和阶段的递增 App 序号。重复回执不续期；本地预算最多 5 秒，另扣界面更新年龄。多 App 中优先保留仍有效的可见回报。每个展示实例最多保留 16 个 App 身份；下一窗口或配置/绑定变化换展示实例并清空，时钟短暂失效不删除序号记录。
- 临时收起许可只是意图；未收到 Hidden 窗口回报前不能声称已经收起。展示消息不属于 NoiseInterruption，不操作麦克风、保护或报告。
- KV 使用独立 `0.13 POST /device/study-settings/presentation`；旧 0.10/0.11/0.12 定义保留。NativeDevice 在取得网络锁后采样，扣除 1 秒 HTTP 预算，KV 再扣等待权限/事务的时间。同一源脉冲不延长服务器到期日；旧上下文、配置、序号或不属于有效校历的窗口被拒绝。复用已有 NpepStudyDevice JSON，不新增迁移。
- Runtime 的观察循环与采集许可独立，旧服务器不支持时 60 秒后再试。受理或网络成功不授予展示/采集权限。暂停或绑定改变会阻断发送与迟到结果；已发布回报经过剩余预算自然失效，并非零延迟撤回。
- 后台分别展示“设备回报展示页可见”“设备回报展示页已收起”“展示执行回执待确认”。服务端检查会话、配置和阶段；网页以 performance.now 扣查询全程和后续停留时间，刷新失败即撤下新鲜声明。

这些是近几秒的窗口与界面更新回报，不能证明教室实体屏幕亮着、无遮挡或学生已看到。目标大屏、真实 ClassIsland、完整 App/Host/Guard 的内存及恢复仍需人工/设备验收；本地小窗口测试不替代这些验收。
